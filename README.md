# The Hidden Economics: production pipeline

A local-first system that turns a researched topic into original, sourced documentaries and
vertical videos using Python and FFmpeg. Nothing is bought, published or sent to a paid API
without explicit human approval.

**Topic 1: "Why Switzerland Is So Rich".** It produces five real MP4s from one shared research
dossier:

| Deliverable | Format | Length | Story |
|---|---|---|---|
| `documentary` | 1920x1080, 16:9 | 8 min 55 s | Cold open + 6 acts + conclusion: puzzle, stability, money, specialisation, skills, hidden costs |
| `short_exports` | 1080x1920, 9:16 | 38.4 s | "More than half of Swiss exports come from one industry" |
| `short_secrecy` | 1080x1920, 9:16 | 46.9 s | Banking secrecy is still law, yet account data is shared since 2018 |
| `extended_franc` | 1080x1920, 9:16 (TikTok) | 76.9 s | The SNB's 1.20 franc floor, 2011-2015 |
| `pilot_horizontal` | 1920x1080, 16:9 | 87.7 s | Phase 1 pilot, kept for reference |

The four Topic 1 deliverables are narrated by the paid OpenAI voice (`gpt-4o-mini-tts`, voice
`onyx`), approved for this topic under a hard US$0.50 cap; the full build billed US$0.29 (9,734
characters). With this slower voice `short_secrecy` runs 46.9 s, so its target was raised to
30-50 s by the editor. `pilot_horizontal` keeps the free Kokoro-82M voice
(`af_heart`). All narration is synchronised to the
visuals, an original music bed and original sound effects. The verticals have burned-in captions
that highlight each word as it is spoken. Previews, QC reports, cost reports and the dossier are in
[`docs/poc/`](docs/poc). The videos themselves are not committed; rebuild them with one command (below).

## Principles

1. **No invented facts.** Narration and on-screen numbers are placeholders such as
   `{{gdppc_che_2023}}`, filled from the dossier. Digits typed by hand fail the build.
2. **Verification is a status, not a vibe.** Each claim is marked `data_derived`, `human_verified`,
   `source_located` or `needs_verification`. Only the first two can be published.
3. **Original or licensed only.** Every frame, the music and the sound effects are generated by
   code. Data and maps are CC BY 4.0 or public domain. Fonts and voices are open-licensed. Each
   one is recorded in `assets/manifest.yaml`, and QC checks it against an allowlist.
4. **Each video tells its own story.** A vertical video has its own script, not a cut-down of the
   long one. Each topic gets its own look, and QC flags videos whose scene structure is too
   similar to an existing one.
5. **Humans decide.** `approve` needs a named reviewer, a clean QC report and no unverified
   claims. The approval is tied to the video's SHA-256 hash. `publish` only assembles
   platform folders and never uploads.
6. **Costs and secrets are controlled.** Paid providers refuse to run without `--allow-paid`.
   Unknown prices are reported as "unknown", never guessed. Keys live only in environment
   variables or `.env`, which git ignores.

## Architecture

```
projects/<slug>/
  project.yaml   sources.yaml                 topic: visual identity + sources/claims
  deliverables/<id>/
    deliverable.yaml  script.yaml  storyboard.yaml     format, story, scenes, thumbnails, metadata
        │
research/dossier.py  ◄── data_sources.py  (World Bank API → licensed mirror → committed snapshot)
        │  claims with URL, dates, status
script.py / storyboard.py  (placeholders filled from the dossier; unsourced-number checks)
        │
tts/  festival · kokoro · piper · espeak · elevenlabs* · openai* · silent    (*paid, opt-in)
        │  one WAV per sentence (cached) → exact sentence times → word timings (timing.py)
render/scenes.py  map (+markers, arrows) · bar_chart · line_chart · timeline · kinetic_text ·
        │         ring_stat · pictogram · ranking · big_number · split_compare · act_title ·
        │         end_card · title_card    (16:9 and 9:16 layouts; scenes render in parallel)
        │         + burned-in captions with the spoken word highlighted (vertical)
render/assemble.py  Pillow frames → FFmpeg x264 per scene → concat
audio.py           narration + original music bed (ducked) + original sound effects → loudness norm
        │
thumbnails.py · metadata.py · exports.py (platform drafts) · qc.py · manifest.py · costs.py
        │
approval.py  approve (named reviewer + video hash) → publish (platform packages, no upload)
```

**Spoken text.** Before synthesis, numbers are written out the way a narrator says them:
"1815" becomes "eighteen fifteen", "$99,557" becomes "ninety-nine thousand five hundred fifty-seven
dollars", and "52.7%" becomes "fifty-two point seven percent". Captions keep the written form.

**Sync.** Each scene lasts lead-in + speech + tail, rounded to whole frames. Sentences are
synthesised one at a time, so sentence boundaries are exact. Word times inside a sentence are
estimated from syllable counts, typically within about 0.2 s. Animations and sound effects fire
on cue phrases (`cue: "In 1815"`).

## Setup

Requirements: Python 3.10+ and FFmpeg. Voices are tried in order: **Kokoro** (best, needs the model
files below), Festival with the CMU ARCTIC `slt` voice, then espeak-ng.

```bash
# 1. System tools
#   Ubuntu/Debian: sudo apt install ffmpeg festival festvox-us-slt-hts espeak-ng fonts-inter
#   macOS:         brew install ffmpeg espeak-ng && brew install --cask font-inter   (Festival: see festvox.org, or use Kokoro)
#   Windows:       use WSL2 (Ubuntu) with the apt line above
#   (Without Inter the renderer falls back to DejaVu Sans or Pillow's built-in font.)

# 2. Python
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.lock         # exact tested versions (or requirements.txt for minimums)

# 3. Optional config (better voices, paid providers)
cp .env.example .env

# 4. Check
python -m hiddeneco tts-check
python -m pytest -q                       # 57 tests, offline
```

### Default voice: Kokoro (free, local, Apache-2.0)

```bash
pip install kokoro-onnx
mkdir -p models/kokoro
B=https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0
curl -L -o models/kokoro/kokoro-v1.0.onnx  $B/kokoro-v1.0.onnx    # ~325 MB
curl -L -o models/kokoro/voices-v1.0.bin   $B/voices-v1.0.bin     # ~28 MB
# sha256 used for the pilot:
#   7d5df8ecf7d4b1878015a32686053fd0eebe2bc377234608764cc0ef3636a6c5  kokoro-v1.0.onnx
#   bca610b8308e8d99f32e6fe4197e7ec01679264efed0cac9140fe9c29f1fbf7d  voices-v1.0.bin
cp .env.example .env    # KOKORO_MODEL_PATH / KOKORO_VOICES_PATH already point at models/kokoro/
```

Change the voice in `config/settings.yaml` (`tts.providers.kokoro.voice`, e.g. `af_heart`,
`am_onyx`, or `bm_george` with `lang: en-gb`). `models/` is git-ignored.

### Premium voice: OpenAI (paid, opt-in)

The editor's choice for new topics is OpenAI `gpt-4o-mini-tts` with voice **`ash`** (picked from
an A/B of `onyx`, `ash` and `sage` on 2026-11-03), configured in `tts.providers.openai`:

- `unit: paragraph`: each script segment goes out as **one** request, so intonation carries
  across sentences instead of resetting at every full stop. Sentence boundaries for captions
  and cues are then found in the audio's own pauses (`timing.paragraph_word_timings`).
- `voice_polish: none`: the global EQ/compression/short-echo chain was tuned for Kokoro and
  made this voice sound metallic.
- `instructions`: storyteller direction (varied rhythm, a beat on key numbers).

`ash` speaks about 15% slower than `onyx`, so new scripts should be written about 15% shorter
for the same runtime. Run it with `--tts openai --allow-paid`; the topic budget cap still applies.
Changing any of these options changes the audio cache key, so rebuilding Topic 1 with them would
pay for the full narration again (~$0.29).

## Commands

```bash
python -m hiddeneco topics                                    # ranked topic proposals
python -m hiddeneco estimate why-switzerland-is-so-rich       # cost estimate BEFORE building
python -m hiddeneco research why-switzerland-is-so-rich       # dossier only
python -m hiddeneco build why-switzerland-is-so-rich          # all deliverables (~30-40 min on 4 CPUs)
python -m hiddeneco build why-switzerland-is-so-rich -d documentary   # the long film only
python -m hiddeneco build why-switzerland-is-so-rich -d vertical            # one deliverable
python -m hiddeneco build why-switzerland-is-so-rich -d horizontal --scenes s03_1815   # re-render one scene
python -m hiddeneco build why-switzerland-is-so-rich --scenes                # reuse all rendered scenes
python -m hiddeneco qc why-switzerland-is-so-rich vertical
python -m hiddeneco approve why-switzerland-is-so-rich vertical --reviewer "Your Name"
python -m hiddeneco publish why-switzerland-is-so-rich vertical   # platform folders; never uploads
```

### Outputs (`output/<slug>/`)

| Path | Contents |
|---|---|
| `research/dossier.md` | Every claim with its status and sources (URL, published date, access date) |
| `<id>/<slug>--<id>.mp4` | The video |
| `<id>/subtitles.srt` | Captions built from word timings |
| `<id>/script/script.md`, `storyboard/storyboard.md` | Rendered script with source notes; scene plan |
| `<id>/thumbnails/` | Three 1280x720 concepts (horizontal) or a 1080x1920 cover (vertical) |
| `<id>/metadata.md` | Titles, description or caption, chapters, tags, sources, credits, AI-voice disclosure |
| `<id>/exports_draft/<platform>/` | YouTube / Shorts / Reels / TikTok folders with a `CHECKLIST.md` and official policy links |
| `<id>/qc/qc_report.md` | Technical QC plus the claims that still block publishing |
| `<id>/cost_report.md` | Estimated vs actual cost per step |
| `<id>/build_manifest.json` | Git commit, tool versions and input hashes, for reproducibility |
| `logs/run.jsonl` | Structured logs (one JSON event per line, with timings) |

### What QC checks

- **Format and duration:** duration against the deliverable target; resolution, codecs and audio
  stream (ffprobe).
- **Picture and sound faults:** black frames, frozen picture, silence gaps, integrated loudness
  and true peak (FFmpeg detectors).
- **Captions:** coverage, monotonic timing, reading speed, and the vertical safe zone.
- **Missing media:** absent media and deliverables.
- **Sourcing:** every sourced claim, unsourced numbers, analysis notes.
- **Licensing:** asset licences against the allowlist.
- **Distinctiveness:** scene structure compared with every other deliverable.

## Clearing the approval gate

QC lists every claim that isn't yet `human_verified` or `data_derived`. For each one:

1. Open the source URL listed in `output/<slug>/research/dossier.md` and read it.
2. In `projects/<slug>/sources.yaml`, set `status: human_verified` and `verified_by: <name>`. If the
   source says something else, correct the claim or cut it from the script.
3. Rebuild, then run `approve`, then `publish`.

## Known limitations of the pilot

- **Voice.** Kokoro `af_heart` is the best free voice that runs locally, but it is still recognisably
  synthetic. Topic 1 was narrated with OpenAI `onyx` sentence by sentence, which the editor found
  robotic; new topics use `ash` with paragraph-level synthesis (see "Premium voice" above).
  ElevenLabs or a human narrator remain options.
- **Fact-checking.** All web-located claims (16 for this topic) are still `source_located`. The build environment
  couldn't reach admin.ch, wipo.int, ige.ch, bazg.admin.ch or api.worldbank.org, so a person
  needs to read those pages before publishing. GDP and population figures are
  computed from a CC BY 4.0 mirror of World Bank data. On a normal connection the pipeline uses
  the official API first.
- **Word timing** is estimated inside each sentence; forced alignment is on the roadmap.
- **Monetization** is never guaranteed. Platform eligibility rules change; each export folder
  links to the official pages so they can be re-checked at publish time.
